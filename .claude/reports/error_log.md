### [2026-07-04] BrowserClient: "Target page, context or browser has been closed"

- **What happened:** After the Chromium process died (crash, or killed manually), every later pipeline run threw `browserContext.newPage: Target page, context or browser has been closed` from `warmedPage`.
- **Why it happened:** `BrowserClient` is a singleton that caches the launched `context`. `getContext()` returned the cached ref unconditionally — once the underlying browser was gone, the dead reference was reused forever and `newPage()` always failed.
- **How it was fixed:** `getContext()` now reuses the context only if `context.browser()?.isConnected()`; otherwise it resets and relaunches. Added a `context.on('close')` handler that nulls `context` + clears cached pages the moment Chromium dies, and a `resetContext()` helper. `warmedPage()` also catches a `newPage()` failure and relaunches once. Verified live: force-closed the context mid-session, next scrape recovered (525 ads both runs).
- **Prevention:** Any long-lived singleton browser/context must validate liveness before reuse and self-heal on close — never hand back a cached handle without checking `isConnected()`.

- **What happened:** Goal: fetch EVERY LBC ad matching filters.
